# Проект «Навар» — паспорт для Claude Code

## Что это
Линейка автономных калькуляторов юнит-экономики для русскоязычных продавцов:
- **navar.html** — для продавцов товаров на Авито (комиссия с мин. удержанием, доля продаж через Авито Доставку, невыкупы, ДРР, налоги УСН/НПД).
- **navar-auto.html** — для авто-перекупов (навар со сделки, навар в день, потолок торга на осмотре, стресс-тест «зависла», стоимость кредитных денег, НДФЛ по документам).
Версия v4.3. Продукт прошёл 10 итераций «разработка → тесты → экспертная критика → фиксы».

## Незыблемые принципы (нарушать нельзя)
1. **Один самодостаточный HTML-файл на продукт.** Работает офлайн, с file://, без сервера. Никаких CDN — внешние библиотеки только вендорить внутрь (так уже встроен lz-string, MIT).
2. **Данные не покидают браузер.** Нет аккаунтов, аналитики, запросов наружу. Персистентность — через URL-hash (lz-string) и экспорт/импорт JSON. localStorage не используем (не работает в ряде окружений).
3. **Вся математика проходит через единые функции** (`netAt`/`calc` для формы, `computeItem` для таблицы/импорта/ссылок). Импорт и hash ПЕРЕСЧИТЫВАЮТ метрики — хранимым цифрам не доверяем (анти-подделка).
4. **Честность выше красоты:** предупреждение при выборе НПД (перепродажа под него не подпадает), «— (не считаешь)» вместо «0 ₽» налога, оговорки про линейность годового темпа. Не удалять и не смягчать.
5. **Релиз только через зелёный конвейер** + поднятие версии и даты в футере («vX.Y · формулы сверены: месяц год»).

## Тестовый конвейер (в корне проекта: runner.js + test.js…test8.js)
`npm install` один раз, затем `node runner.js` — 8 наборов, ~79 проверок в jsdom: эталонные расчёты (посчитаны вручную, независимо от кода), налоги, крайние случаи (цена 0, невыкуп 200%), XSS через имя, импорт с подделанными цифрами, восстановление из ссылки в новой сессии, сортировка/редактирование, дебаунс hash (800 мс — лимит Safari на replaceState, не уменьшать). Пути к html — через `NAVAR_DIR` или текущая папка. Правило: упал тест → чини код, эталоны неприкосновенны (если поведение меняется намеренно — эталон обновляется с ручным пересчётом в комментарии).

## Ключевые решения и их причины (не переспрашивать)
- Бинарный поиск (60 итераций) вместо формул в `priceFor`/`maxBuyFor`: кусочные функции (мин. удержание × налоги × доля доставки), формулы хрупки.
- `type=text inputmode=decimal` вместо number: приём «450 000», формат тысяч на blur, шрифт 16px против iOS-зума.
- Дублирование ~70% кода между файлами — ИЗВЕСТНЫЙ долг, лечится сборкой из шаблона (задача №2 ниже).
- Заголовок вкладки без цифр — приватность.

## Задачи первой сессии (по порядку)
1. `git init`, первый коммит, прогнать конвейер на этой машине.
2. Открыть оба файла в реальном браузере (впервые!), прокликать: липкая строка на мобильной ширине, «Точная настройка», сортировка, ✎-редактирование, «Ссылка на расчёт», «Картинка для чата», экспорт/импорт. Найденное — чинить через конвейер.
3. Собрать оба продукта из единого шаблона (устранить дублирование), конвейер должен остаться зелёным без правки эталонов.
4. Деплой на GitHub Pages: /navar и /avto.
5. Дальше — план запуска: посевные тексты для чатов селлеров и перекупов («где вру?»-формат), Telegram-канал, кнопка-заглушка «199 ₽/мес» для замера спроса (только сбор контактов, не продажа).

## Тулинг (настроить в первой сессии, до задач)
- **MCP не ставим** (решение 2026-07-28): GitHub закрыт встроенным `gh` CLI, живой браузер — встроенной панелью Browser Claude Code (клики, скриншоты, мобильный viewport). Лишние MCP съедают контекст.
- **Хук после правок** (настроен): `.claude/settings.json` + `.claude/hooks/run-pipeline.js` — после каждого изменения *.html автоматически запускается `node runner.js`; сломанный код не должен покидать сессию.
- **Slash-команды** в `.claude/commands`: `/release` = конвейер → поднять версию и дату в футерах → коммит → деплой; `/critique` = сухой проход экспертом по чек-листу (методика, UX, крайние случаи, честность оговорок).
- **Экономия токенов:** одна сессия — одна задача из списка выше; `/compact` в длинных сессиях, `/clear` между несвязанными задачами; рутину (тесты, мелкие правки) — на быстрой модели, архитектуру — на старшей.
- **Трафик-тулинг:** Fetch/поиск MCP — мониторить изменения тарифов Авито (каждое изменение = контент-повод и обновление дефолтов); после появления сайта — Google Search Console API для чтения поисковых запросов. Трафик делается контентом и посевами, плагины его не заменяют.

## Стиль работы с владельцем
Работать циклом «сделал → протестировал → сам покритиковал как эксперт → исправил → показал результат с отчётом». Не выдавать сырьё и не спрашивать разрешения на промежуточные шаги. Критика — сухая, по пунктам. Финансовые/налоговые формулировки менять осторожно: это справочный инструмент, не консультация.
